# MECCHA CHAMELEON Clone (Roblox)

Клон механик Steam-игры [MECCHA CHAMELEON](https://store.steampowered.com/app/4704690/MECCHA_CHAMELEON)
на движке Roblox: прятки + рисование.

## Суть игры

Игроки делятся на две команды:

- **Hiders (прячущиеся)** — стартуют полностью белыми. Их задача: свободно
  нарисовать кистью на своём теле цвета и паттерны окружения (стены, пол,
  мебель) — не залить одним цветом, а именно нарисовать мазками, как
  художник по холсту, — а затем выбрать одну из 4 конкретных поз (присесть,
  лечь, прислониться, замереть стоя), имитируя часть интерьера. Во время
  поиска у каждого Hider работает свисток: автоматический раз в 45 секунд
  или вручную по желанию игрока — звуковая подсказка искателям.
- **Seekers (искатели)** — ищут всех Hiders до конца таймера раунда. Пойманный
  Hider не выбывает: по умолчанию (режим Infection) он мгновенно снимает позу
  и покраску и сам становится Seeker, продолжая охоту вместе с остальными.

Побеждают Seekers, если находят всех. Побеждают Hiders, если хотя бы один
остался не найден. Игра рассчитана на публичные лобби от 2 до 24 игроков
(точный верхний предел на сервере зависит от размера карты — см. раздел
"MaxPlayers" ниже). Игрок, зашедший на сервер посреди активного раунда,
становится зрителем (свободная летающая камера, не участвует) до конца
текущего раунда, а затем автоматически включается в раздачу ролей. Можно
также создать приватную комнату с паролем для игры с друзьями (аналог
"Custom Game" из оригинала).

## Как это устроено (кратко)

1. **Лобби** — ждём, пока наберётся минимум игроков, идёт обратный отсчёт.
2. **Фаза пряток (Hiding)** — Hiders красятся и занимают позу, Seekers ждут в
   отдельной комнате.
3. **Фаза поиска (Seeking)** — Seekers выпускают, они ищут Hiders до конца
   таймера или пока не найдут всех. В режиме Infection (по умолчанию) число
   искателей растёт по ходу раунда — каждый пойманный Hider тут же
   присоединяется к поиску.
4. **Итоги раунда** — начисляются очки, показывается экран результатов, игра
   возвращается в лобби.

Подробное техническое описание решений — в `DECISIONS.md`. Прогресс и этапы —
в `ROADMAP.md` и `TASKS.md`.

## Как перенести проект в Roblox Studio

**Вариант А — через Rojo (рекомендуется):**

1. Установи [Rojo](https://rojo.space/) — плагин для Roblox Studio (ищется в
   Toolbox как "Rojo") и command-line инструмент (по инструкции с сайта rojo.space).
2. В папке проекта выполни `rojo serve` (это делает Claude или тот, у кого
   настроен терминал).
3. В Studio открой плагин Rojo → Connect. Файлы из `src/` появятся в дереве
   игры в нужных сервисах автоматически, согласно `default.project.json`.

**Вариант Б — вручную (без Rojo):**

1. Открой каждый `.lua` файл из `src/...` и скопируй его содержимое.
2. В Studio создай Script/LocalScript/ModuleScript с таким же именем в
   соответствующем сервисе (см. таблицу ниже) и вставь код.

| Расширение файла | Тип объекта в Studio | Где создавать |
|---|---|---|
| `*.server.lua` | `Script` | ServerScriptService |
| `*.client.lua` | `LocalScript` | StarterPlayer → StarterPlayerScripts |
| `*.lua` (без суффикса) | `ModuleScript` | там же, где лежит в `src/` |

## Что нужно вручную настроить в самой карте (Workspace)

Карта (включая лобби-платформу и маркер `SeekerWaitingRoom`) строится
кодом автоматически при старте сервера (`MapBuilder.lua`, см.
`DECISIONS.md`, п.23 и п.25) — вручную создавать её части не нужно.
Руками нужно донастроить только:

- **Avatar Type = R15** в Studio (Game Settings → Avatar) — риг, под
  который рассчитан белый "пластилиновый" стиль персонажей
  (`CharacterStyleService.lua`, см. `MEGA_PLAN.md`, Часть 2). Кодом не
  задаётся — это настройка места.
- Реальные **Animation ID** для всех 4 пресетов позы вместо заглушек
  `rbxassetid://0` в `PosePresets.lua` (`animationId` каждого пресета) —
  загрузи 4 отдельные анимации через Studio и подставь ID.
- Реальная **картинка мазка кисти** вместо заглушки `rbxassetid://0` в
  `GameConfig.BRUSH_STAMP_IMAGE_ID` (мягкий белый кружок, тонируется в любой
  цвет через `Color3` — без мазка кисть будет невидимой).
- Реальный **звук свистка** вместо заглушки `rbxassetid://0` в
  `GameConfig.WHISTLE_SOUND_ID`.
- Локация с разнообразными цветами/текстурами для покраски (стены, мебель,
  декорации) — чем разнообразнее, тем интереснее играть в пипетку и рисовать
  под них паттерны.

## Требования к количеству игроков и настройка MaxPlayers

`GameConfig.MIN_PLAYERS_TO_START = 2` и `GameConfig.MAX_PLAYERS = 24` -
диапазон, на который рассчитана формула распределения ролей (см.
`DECISIONS.md`, п.19). **Важно:** `GameConfig.MAX_PLAYERS` - это только
справочное значение для расчётов внутри кода. Реальный лимит игроков на
сервер код задать не может - это делается отдельно, вручную, в
**Creator Dashboard** (creator.roblox.com → твой experience → Basic Settings
→ Max Players), не в Studio и не в файлах проекта.

**Какое значение выставить:** сейчас у проекта ещё нет полноценной большой
карты, поэтому для MVP-тестирования рекомендуется начать с **10-12**
игроков на сервер - этого достаточно, чтобы проверить механику и формулу
ролей, не требуя от карты вмещать толпу. Когда появится финальная карта
подходящего размера, лимит можно постепенно поднимать вплоть до **24**
(верхняя граница, под которую рассчитан баланс, см. `DECISIONS.md`, п.19) -
чем больше карта и чем больше на ней укрытий, тем больше игроков она
способна интересно вместить одновременно.
