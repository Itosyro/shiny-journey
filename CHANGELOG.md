## 2026-07-08 — Фикс V2: троттлинг сэмплинга рисования

Третья задача из `TASKS.md` Раздела A, рецепт — `MEGA_PLAN.md` 3.1.3.
`PaintClient.lua`, `addStrokePoint`: `InputChanged` может приходить с

## 2026-07-08 — Фикс V1: снижен потолок мазков на игрока

Вторая задача из `TASKS.md` Раздела A, рецепт — `MEGA_PLAN.md` 3.1.2.
`GameConfig.MAX_ACTIVE_STAMPS_PER_PLAYER` 400 → 150 — при 24 игроках
на слабом мобильном раньше это могло означать до 9600 Texture-
инстансов одновременно на карте. 150 всё ещё с запасом хватает на

только автором в Studio. Следующая задача — V2 (троттлинг рисования).

## 2026-07-08 — Фикс K1: промпт поимки после Reset Character

Первая задача из `TASKS.md` Раздела A (план после аудита Fable 5),
рецепт — `MEGA_PLAN.md` 3.1.1. `CatchService.lua`: Hider, нажавший
"Reset Character" посреди фазы поиска, терял `ProximityPrompt` вместе
со старым телом и становился неуловимым — в режиме Infection раунд не
мог завершиться досрочно, если оставался только такой игрок. Добавлен
`Players.PlayerAdded` → `CharacterAdded`-обработчик (`onCharacterRespawn`,
по образцу `SpectatorService.Init`): для живого непойманного Hider
(`foundState[player] == false`) промпт перевешивается на новое тело и
снова прячется от всех Hiders через `HideCatchPromptsFromHiders` (роль
определяется через уже существующий `RoleUtil.IsHider`). Следующая
задача по очереди — V1 (потолок мазков).

## 2026-07-08 — Первая играбельная карта (процедурная генерация)

По прямому указанию автора: у проекта не было ни одной карты - без неё
всё уже реализованное игровое ядро было невозможно проверить вживую.

- Веб-поиск бесплатных готовых карт/мебели под жанр "прятки в помещении" -
  найдено 5 вариантов (Roblox Marketplace/Creator Store/Library-ассеты,
  Blender-файл, `.rbxl`-шаблон целой игры). Ни один не подошёл: активы
  Marketplace/Creator Store по их же условиям использования запрещено
  использовать вне Roblox Studio (нельзя легально выгрузить как файл и
  закоммитить в открытый репозиторий), а остальные - либо не в формате
  Roblox, либо без явной лицензии на встраивание. Полная таблица со
  ссылками и разбором лицензий - новый файл `MAPS.md`.
- `MapBuilder.lua` (новый серверный модуль) - карта строится кодом из
  примитивов `Part` при старте сервера, без единого внешнего ассета:
  открытая планировка из 3 зон (Лобби / Рабочая зона с "Офисом" и
  "Складом" / Гостиная с "Переговорной"), ~40 предметов мебели разного
  цвета/размера (важно для маскировки кистью), полновысотные стены с
  проёмом 12 стадов между зонами (реально блокируют
  `LineOfSightUtil` - поимку и Missed Point Ranking) плюс низкие
  декоративные перегородки внутри зон (не блокируют). Крыш у комнат нет -
  осознанно, дешевле по производительности и даёт зрителю обзор сверху.
- `SeekerWaitingRoom` (Part-контракт, заложенный ещё в `DECISIONS.md`,
  п.9) наконец физически создан - отдельная запертая комната без дверей,
  доступна только телепортом.
- Новый Part-контракт `SpectatorSpawn` - точка высоко над картой;
  `SpectatorService.hideAndImmobilize` теперь телепортирует туда нового
  зрителя перед анкором, чтобы сразу дать обзор карты сверху.
- `GameConfig.USE_PROCEDURAL_MAP` (новая константа) - переключатель
  генерации на будущее, если появится готовая карта из Studio.
- `Main.server.lua`: `MapBuilder.Build()` вызывается первым действием при
  старте сервера.
- Автор прислал команду для локальной установки MCP-плагина Roblox Studio
  (Windows, `%LOCALAPPDATA%\Roblox\mcp.bat`) - подтверждено и
  задокументировано в `TASKS.md` ("Live Test Findings"), что это команда
  для локальной сессии Claude Code на компьютере автора, не для этой
  облачной сессии (нет `cmd.exe`/Windows-путей) - не выполнялась здесь.

Обновлены `ARCHITECTURE.md` (новый раздел "Карта"), `DECISIONS.md` (п.23),
`TASKS.md` (новый Раздел 0.9, новые сценарии в Разделе 4, дополнение к
"Live Test Findings"), `MAPS.md` (новый файл).

## 2026-07-06 — Missed Point Ranking + первая попытка живого MCP-плейтеста

По прямому указанию автора: добавлена механика очков "Missed Point
Ranking" из оригинала (Hider награждается за то, что остаётся в зоне
видимости Seeker'а и всё равно не замечен), плюс первая попытка живого
теста через Roblox Studio MCP.

**Missed Point Ranking (см. `DECISIONS.md`, п.22):**
- `LineOfSightUtil.lua` (новый общий модуль, `ServerScriptService`) —
  математика дистанции + прямого взгляда (raycast), вынесенная из
  `CatchService.lua`, чтобы её же переиспользовал `ScoreService.lua` без
  дублирования. Поведение поимки не изменилось.
- `GameConfig.lua` — `MISSED_POINT_CHECK_INTERVAL_SECONDS` (1.5с, не чаще
  раза в 1-2 секунды — требование задачи и `CLAUDE.md` про мобильную
  производительность), `MISSED_POINT_MAX_DISTANCE` (50 — шире, чем
  дистанция поимки), `MISSED_POINT_PER_TICK` (3), `SURVIVAL_BONUS_POINTS`
  (50, отдельный флат-бонус за выживание до конца раунда).
- `ScoreService.lua` — фоновый цикл во время фазы поиска (тот же паттерн
  "токена раунда", что и в `WhistleService.watchLoop`): каждые
  `MISSED_POINT_CHECK_INTERVAL_SECONDS` проверяет каждого живого Hider
  против всех живых Seekers; роль читается из live `player.Team`, поэтому
  счётчик сам останавливается, как только Hider становится Seeker в
  Infection — без необходимости знать о мутациях `RoundManager`.
- Новый RemoteEvent `MissedPointRankingUpdate` — **только самому Hider'у**,
  в реальном времени. **Явное решение: Seeker эту метрику не видит вообще**,
  ни в реальном времени, ни с задержкой — даже throttled-пинг раз в 30
  секунд остаётся сигналом "рядом кто-то есть", подрывающим саму суть
  механики (обоснование — `DECISIONS.md`, п.22).
- `HUDBuilder.lua`/`RoundUIClient.lua` — личный лейбл "Замечен, но не
  пойман! Маскировка: N".
- `ResultsUIBuilder.lua` — экран итогов теперь показывает "🏆 Топ раунда"
  (топ-3 по `roundScore`) и, если применимо, "🎭 Лучшая маскировка раунда"
  (максимум `missedPoints`) перед полным списком участников.
- Подтверждено без изменений кода: очки Infection-игрока (Hider → Seeker)
  уже складываются корректно, т.к. `roundScores` — плоская таблица по
  игроку, не привязанная к роли (тот же вывод, что и раньше в п.18).

**Первая попытка живого теста через Roblox Studio MCP:**
- Подтверждено (`ListConnectors` + поиск инструментов по ключевым словам):
  MCP-плагин Roblox Studio недоступен в этой сессии Claude Code on the

- Подробности и инструкция для автора (простыми словами, что делать
  дальше) — `TASKS.md`, Раздел 1, "Live Test Findings".

Обновлены `ARCHITECTURE.md` (диаграмма, таблицы RemoteEvents/состояния,

## 2026-07-06 — Лобби, гибкий баланс ролей 2-24, приватные комнаты, режим зрителя

По прямому указанию автора: предыдущая оценка "целевой баланс 6-8 игроков"
была ошибочной — реальные публичные лобби оригинала рассчитаны на 2-24
игрока в зависимости от режима/карты. Баланс пересмотрен под эти цифры,
плюс добавлены приватные комнаты с паролем (Custom Game из оригинала),
полноценный режим зрителя для зашедших посреди раунда и экран лобби.

**Баланс ролей (см. `DECISIONS.md`, п.19):**
- `GameConfig.lua` — `MAX_PLAYERS` 10→24, `MAX_SEEKERS` 3→5, раздельные
  делители `SEEKERS_PER_PLAYERS_CLASSIC = 5` / `_INFECTION = 8` вместо
  одного общего (Infection стартует с меньшим числом Seekers — оно и так
  вырастет по ходу раунда за счёт заражения, см. п.18).
- `PlayerRoleService.calculateSeekersCount` выбирает делитель по
  `GameMode.Current`. Проверено на границах: 2 игрока → 1 Seeker (оба
  режима), 24 игрока → 4 Seekers (Classic) / 3 Seekers (Infection).

**Приватные комнаты (см. `DECISIONS.md`, п.20):**
- `PrivateRoomService.lua` (новый) — создание/вход по паролю через
  `TeleportService:ReserveServerAsync`/`TeleportAsync` (актуальный метод,
  не устаревший `TeleportToPrivateServer`) + `MemoryStoreService` (пароль →
  код сервера, TTL 6 часов, общее хранилище для всех серверов игры).
  Рейт-лимит и на создание, и на вход; нормализация и валидация пароля.
- `UI/LobbyUIBuilder.lua` + `LobbyUIClient.lua` (новые) — экран лобби:
  список игроков, статус ожидания/отсчёта, кнопки "Создать комнату"/"Войти
  по паролю" с оверлеем ввода и показом ошибок с сервера.
- Новые RemoteEvent: `CreatePrivateRoom`, `JoinPrivateRoom`,
  `PrivateRoomError`.
- **Важное ограничение:** `TeleportService` не работает в Play-режиме
  Roblox Studio — проверить создание/вход можно только после публикации.

**Режим зрителя (см. `DECISIONS.md`, п.21):**
- `SpectatorService.lua` (новый, сервер) — игрок, зашедший посреди
  активной фазы, скрывается (`Transparency=1`, `CanCollide=false`),
  обездвиживается (`WalkSpeed=0`) и анкорится до конца раунда;
  `RoundManager` вызывает `ExitSpectator` (полный респавн через
  `LoadCharacter`) для всех, кому назначена роль в новом раунде.
- `SpectatorClient.lua` (новый, клиент) — fly-камера через
  `Humanoid.MoveDirection` (официально не зависит от `WalkSpeed` —
  подтверждено Creator Hub) + две простые кнопки вверх/вниз, без единой
  строчки кастомного управления вводом/камерой.
- `RoundManager.lua` — `setWalkable(player, true)` пропускается для
  игроков, ещё летающих зрителем (и в обычном завершении раунда, и в
  аварийном pcall-восстановлении).
- Новый RemoteEvent `SpectatorModeChanged`.

**Прочее:**
- `PaintClient.lua` — панели кисти/пипетки/чернил теперь скрыты для
  не-Hider и вне фазы Hiding (тот же паттерн клиентского гейтинга, что уже
  был у `FreezeClient.lua`; заодно закрывает старый пункт из Раздела 0.6
  "скрыть UI кисти для только что инфицированного Seeker").
- `Main.server.lua`/`Main.client.lua` — подключены новые сервисы/клиенты.

**Найдено и исправлено на код-ревью перед коммитом** (skill `code-review`,
8 углов анализа):
- `SpectatorService`'s обработчик `CharacterAdded` не проверял, участвует
  ли игрок уже в текущем раунде — стандартная кнопка "Reset Character"
  превращала бы живого Hider/Seeker в невидимого обездвиженного зрителя до
  конца раунда. Плюс тот же обработчик никогда не выставлял команду
  "Spectators" настоящим новым зрителям (единственная функция, которая это
  делала, не вызывалась на реальном пути входа). Исправлено общей функцией
  `becomeSpectator` + явной проверкой `player.Team`.
- `PrivateRoomService.onCreatePrivateRoom` не имел рейт-лимита (в отличие
  от входа) и трактовал сбой проверки занятости пароля как "пароль
  свободен" — оба исправлены.
- `SpectatorClient.startFlying` мог тихо не запустить полёт при медленной
  репликации персонажа (таймаут `WaitForChild`) — заменено на ожидание без
  таймаута в `task.spawn` с защитой от гонки через счётчик поколений.
- Извлечён общий `ReplicatedStorage/Modules/RoleUtil.lua`

## 2026-07-05 — Пересмотр механики покраски на кисть + новая механика свистка

По прямому указанию автора: предыдущая реализация покраски (кнопки "выбрать
часть тела → залить цветом") была признана **неверной по механике**
относительно оригинала MECCHA CHAMELEON. Игрок должен свободно рисовать
кистью по телу, как по холсту, с возможностью повторить паттерн окружения, а
не просто "стать одного цвета". Переписано полностью, плюс добавлена новая
механика свистка (которой раньше не было в проекте).

**Технологическое решение (см. `DECISIONS.md`, п.14 — с обоснованием):**
рассмотрены `EditableImage`/`EditableMesh` (официальный in-experience API
рисования пикселей) и отклонены по трём причинам, подтверждённым через
DevForum и Creator Hub: (1) не реплицируется сервер→клиент "из коробки" -
пришлось бы городить свою систему синхронизации пиксельных буферов; (2)
требует ID-верификации владельца эксперимента для публикации; (3) сложная
барицентрическая математика UV. Вместо этого выбран подход
"stamp-based painting": маленькие тонированные `Texture`-мазки (свойства
`Color3`, `StudsPerTileU/V`, `OffsetStudsU/V` — стабильный API без
ограничений), реплицируются автоматически как обычные Instance.

**Новые/переписанные файлы:**
- `ReplicatedStorage/Modules/BrushGeometry.lua` (новый) — общая математика
  face/UV для мазков, используется и клиентом, и сервером, чтобы не
  дублировать/не рассинхронизировать её.
- `ServerScriptService/PaintService.lua` (переписан) — "чернила" (0-100)
  вместо дискретных зарядов, приём и валидация пакетов точек мазка
  (`PaintStroke`, батчинг раз в ~0.15с — не по одной точке за раз), создание
  `Texture`-мазков, лимит мазков на игрока (`MAX_ACTIVE_STAMPS_PER_PLAYER`,
  FIFO), явные проверки роли (только Hider) и фазы (только `Hiding`) —
  закрывает ранее скрытую слабость проверки (Seeker технически не был явно
  заблокирован, спасала только случайность инициализации данных).
- `StarterPlayer/StarterPlayerScripts/PaintClient.lua` (переписан) —
  "покрасочная камера" (`CameraType.Scriptable`, фиксированный ракурс на
  себя), рисование зажатием пальца/мыши с мазками по собственному телу
  (raycast с `FilterType = Include` только на свой персонаж), пипетка
  осталась прежней (работает в обычной камере, недоступна во время рисования).
- `UI/PaletteUIBuilder.lua` (переписан) — убрана строка выбора части тела.
- `UI/BrushControlsUIBuilder.lua` (новый) — самодельный touch-слайдер размера
  кисти (Roblox не имеет готового GUI-слайдера) + кнопка входа/выхода в режим
  рисования.
- `ServerScriptService/WhistleService.lua` (новый) — автоматический свисток
  каждые `WHISTLE_AUTO_INTERVAL_SECONDS` (45с) в фазу `Seeking`, ручной
  свисток по запросу клиента сбрасывает таймер, позиционный `Sound` с
  `RollOffMinDistance`/`RollOffMaxDistance` (слышен только в радиусе).
  Серверный "токен раунда" останавливает фоновый цикл проверки таймеров между
  раундами без утечки параллельных циклов.
- `StarterPlayer/StarterPlayerScripts/WhistleClient.lua` (новый) — кнопка
  "Свистнуть" + полоска обратного отсчёта, видна только Hiders в фазу поиска.
- `RemotesSetup.lua` — `PaintCharacter`→`PaintStroke`, `BrushChargesUpdate`→
  `InkUpdate`, добавлены `RequestWhistle`/`WhistleCountdownUpdate`.
- `RoundManager.lua`/`Main.server.lua`/`Main.client.lua` — подключены новые
  сервисы; `PaintService.ResetCharges` заменён на `ResetForNewRound` (стирает
  и чернила, и мазки прошлого раунда — Hider каждый раунд снова стартует
  полностью белым).

**Известные ограничения (честно зафиксированы, требуют живого теста):**

## 2026-07-05 — Дизайн-решения по итогам аудита Opus (внедрено Sonnet)

Автор ответил на оба открытых дизайн-вопроса из аудита Opus (см. запись ниже)
и попросил внести изменения. Реализовано:

**1. Подсказка "Поймать" больше не раскрывает Hiders:**
- `CatchService.lua`: убран `prompt.ObjectText = hiderPlayer.Name` (подсказка
  теперь нейтральная — только `ActionText = "Поймать"`, без имени).
- Включено `prompt.RequiresLineOfSight = true` (встроенная проверка Roblox).
- Добавлена собственная серверная проверка `hasLineOfSight` (raycast от
  `Head` искателя до `HumanoidRootPart` цели) — встроенное свойство
  `RequiresLineOfSight` само по себе только клиентское и обходится тем же
  эксплойтом `fireproximityprompt`, что и дистанция (проверено веб-поиском по
  документации и DevForum), поэтому продублировано на сервере в `TryCatch`.
- Подсказка теперь **видна только Seekers**: `CatchService.StartSeekingPhase`
  собирает все созданные `ProximityPrompt` и рассылает их персонально каждому
  Hider через новый RemoteEvent `HideCatchPromptsFromHiders`; клиент (новый
  файл `CatchClient.lua`) локально выставляет им `Enabled = false`. Seekers
  этот remote не получают и видят подсказки как раньше. Паттерн подтверждён
  через DevForum (клиентское переопределение `Enabled` не влияет на сервер и
  других игроков).

**2. Поза — только для Hiders, только в фазу Hiding:**
- `FreezeService.onRequestFreeze` теперь проверяет: игрок должен быть в
  команде Hiders и текущая фаза (`RoundManager.State`) должна быть `"Hiding"`
  — иначе запрос молча отклоняется. `FreezeService.lua` подключил
  `RoundManager` через `require` (без цикла зависимостей, т.к. `RoundManager`
  получает сервисы через `Init()`, а не `require()`).
- `FreezeClient.lua`: кнопка позы скрыта (`Visible = false`) для Seekers и
  неактивна (`Active = false`, затемнена) вне фазы `Hiding` — зеркалит
  серверное ограничение для UX, реальная защита всегда на сервере.
- Зафиксирован сознательный компромисс в `DECISIONS.md` п.13: теперь Hider не
  может переключить позу и во время `Seeking` (не только заморозиться, но и
  разморозиться) — это убирает более раннюю идею "спалиться на движении при
  разморозке" из исходного ТЗ. Если понадобится вернуть — однострочная правка
  условия фазы в `FreezeService`.

**Документация:** обновлены `ARCHITECTURE.md` (новый RemoteEvent, новая
структура `CatchService`/`FreezeService`, зависимость `FreezeService` →
`RoundManager`), `DECISIONS.md` (новые пункты 12 и 13), `TASKS.md` (два
