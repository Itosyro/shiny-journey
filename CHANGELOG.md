# CHANGELOG

Журнал изменений по датам. Ведётся, чтобы можно было продолжить работу в
любой новой сессии (или с другой нейросетью) без потери контекста.

## 2026-07-08 — Фикс S9: не слать InkUpdate вне фазы Hiding/Lobby

Девятая и последняя задача из `TASKS.md` Раздела A3 (S1-S9 закрыты).
`PaintService.rechargeLoop` слал `InkUpdate` всем клиентам каждую
секунду вне зависимости от фазы - лишний трафик там, где полоску
чернил всё равно не видно. Теперь отправка идёт только в `Hiding` и
`Lobby` (регенерация чернил в фоне продолжается всегда) - условие сразу
взято в редакции `MEGA_PLAN.md` 1.3.4, с учётом будущей кисти в лобби
(B1.3), чтобы не переделывать это условие повторно. Этим закрыт весь
`TASKS.md` Раздел A (K1, V1-V5, S1-S9) - следующая очередь работ:
Раздел B1 (лобби-платформа, `MEGA_PLAN.md` Часть 1).

## 2026-07-08 — Фикс S5: длина пароля приватной комнаты в символах, не байтах

Пятая задача из `TASKS.md` Раздела A3. `PrivateRoomService.
isValidPassword` считал `#password` - это байты, а не символы: 4
кириллические буквы это 8 байт, поэтому фактический минимум для
русского пароля был 2 буквы вместо задуманных 4. Заменено на
`utf8.len(password)`. Заодно расширен и задокументирован комментарий
про `lower()` - кириллица регистрозависима ("ДОМ1" ≠ "дом1"), это
сознательный компромисс, подсказка добавлена в placeholder поля пароля
(`LobbyUIBuilder.lua`). Следующая задача — S6 (косметика карты).

## 2026-07-05 — Пересмотр механики покраски на кисть + новая механика свистка

По прямому указанию автора: предыдущая реализация покраски (кнопки "выбрать
часть тела → залить цветом") была признана **неверной по механике**
относительно оригинала MECCHA CHAMELEON. Игрок должен свободно рисовать
кистью по телу, как по холсту, с возможностью повторить паттерн окружения, а
не просто "стать одного цвета". Переписано полностью, плюс добавлена новая
механика свистка (которой раньше не было в проекте).

**Технологическое решение (см. `DECISIONS.md`, п.14 — с обоснованием):**
рассмотрены `EditableImage`/`EditableMesh` (официальный in-experience API
рисования пикселей) и отклонены по трём причинам, подтверждённым через
DevForum и Creator Hub: (1) не реплицируется сервер→клиент "из коробки" -
пришлось бы городить свою систему синхронизации пиксельных буферов; (2)
требует ID-верификации владельца эксперимента для публикации; (3) сложная
барицентрическая математика UV. Вместо этого выбран подход
"stamp-based painting": маленькие тонированные `Texture`-мазки (свойства
`Color3`, `StudsPerTileU/V`, `OffsetStudsU/V` — стабильный API без
ограничений), реплицируются автоматически как обычные Instance.

**Новые/переписанные файлы:**
- `ReplicatedStorage/Modules/BrushGeometry.lua` (новый) — общая математика
  face/UV для мазков, используется и клиентом, и сервером, чтобы не
  дублировать/не рассинхронизировать её.
- `ServerScriptService/PaintService.lua` (переписан) — "чернила" (0-100)
  вместо дискретных зарядов, приём и валидация пакетов точек мазка
  (`PaintStroke`, батчинг раз в ~0.15с — не по одной точке за раз), создание
  `Texture`-мазков, лимит мазков на игрока (`MAX_ACTIVE_STAMPS_PER_PLAYER`,
  FIFO), явные проверки роли (только Hider) и фазы (только `Hiding`) —
  закрывает ранее скрытую слабость проверки (Seeker технически не был явно
  заблокирован, спасала только случайность инициализации данных).
- `StarterPlayer/StarterPlayerScripts/PaintClient.lua` (переписан) —
  "покрасочная камера" (`CameraType.Scriptable`, фиксированный ракурс на
  себя), рисование зажатием пальца/мыши с мазками по собственному телу
  (raycast с `FilterType = Include` только на свой персонаж), пипетка
  осталась прежней (работает в обычной камере, недоступна во время рисования).
- `UI/PaletteUIBuilder.lua` (переписан) — убрана строка выбора части тела.
- `UI/BrushControlsUIBuilder.lua` (новый) — самодельный touch-слайдер размера
  кисти (Roblox не имеет готового GUI-слайдера) + кнопка входа/выхода в режим
  рисования.
- `ServerScriptService/WhistleService.lua` (новый) — автоматический свисток
  каждые `WHISTLE_AUTO_INTERVAL_SECONDS` (45с) в фазу `Seeking`, ручной
  свисток по запросу клиента сбрасывает таймер, позиционный `Sound` с
  `RollOffMinDistance`/`RollOffMaxDistance` (слышен только в радиусе).
  Серверный "токен раунда" останавливает фоновый цикл проверки таймеров между
  раундами без утечки параллельных циклов.
- `StarterPlayer/StarterPlayerScripts/WhistleClient.lua` (новый) — кнопка
  "Свистнуть" + полоска обратного отсчёта, видна только Hiders в фазу поиска.
- `RemotesSetup.lua` — `PaintCharacter`→`PaintStroke`, `BrushChargesUpdate`→
  `InkUpdate`, добавлены `RequestWhistle`/`WhistleCountdownUpdate`.
- `RoundManager.lua`/`Main.server.lua`/`Main.client.lua` — подключены новые
  сервисы; `PaintService.ResetCharges` заменён на `ResetForNewRound` (стирает
  и чернила, и мазки прошлого раунда — Hider каждый раунд снова стартует
  полностью белым).

**Известные ограничения (честно зафиксированы, требуют живого теста):**
размещение мазков — плоская проекция на грань детали, не honest UV-wrap по

справочный ориентир для будущей настройки баланса (диапазон 2-10 игроков не
менялся — см. `DECISIONS.md`, п.16).

Обновлены `ARCHITECTURE.md` (новые RemoteEvents, новая структура состояния,

## 2026-07-05 — Дизайн-решения по итогам аудита Opus (внедрено Sonnet)

Автор ответил на оба открытых дизайн-вопроса из аудита Opus (см. запись ниже)
и попросил внести изменения. Реализовано:

**1. Подсказка "Поймать" больше не раскрывает Hiders:**
- `CatchService.lua`: убран `prompt.ObjectText = hiderPlayer.Name` (подсказка
  теперь нейтральная — только `ActionText = "Поймать"`, без имени).
- Включено `prompt.RequiresLineOfSight = true` (встроенная проверка Roblox).
- Добавлена собственная серверная проверка `hasLineOfSight` (raycast от
  `Head` искателя до `HumanoidRootPart` цели) — встроенное свойство
  `RequiresLineOfSight` само по себе только клиентское и обходится тем же
  эксплойтом `fireproximityprompt`, что и дистанция (проверено веб-поиском по
  документации и DevForum), поэтому продублировано на сервере в `TryCatch`.
- Подсказка теперь **видна только Seekers**: `CatchService.StartSeekingPhase`
  собирает все созданные `ProximityPrompt` и рассылает их персонально каждому
  Hider через новый RemoteEvent `HideCatchPromptsFromHiders`; клиент (новый
  файл `CatchClient.lua`) локально выставляет им `Enabled = false`. Seekers
  этот remote не получают и видят подсказки как раньше. Паттерн подтверждён
  через DevForum (клиентское переопределение `Enabled` не влияет на сервер и
  других игроков).

**2. Поза — только для Hiders, только в фазу Hiding:**
- `FreezeService.onRequestFreeze` теперь проверяет: игрок должен быть в
  команде Hiders и текущая фаза (`RoundManager.State`) должна быть `"Hiding"`
  — иначе запрос молча отклоняется. `FreezeService.lua` подключил
  `RoundManager` через `require` (без цикла зависимостей, т.к. `RoundManager`
  получает сервисы через `Init()`, а не `require()`).
- `FreezeClient.lua`: кнопка позы скрыта (`Visible = false`) для Seekers и
  неактивна (`Active = false`, затемнена) вне фазы `Hiding` — зеркалит
  серверное ограничение для UX, реальная защита всегда на сервере.
- Зафиксирован сознательный компромисс в `DECISIONS.md` п.13: теперь Hider не
  может переключить позу и во время `Seeking` (не только заморозиться, но и
  разморозиться) — это убирает более раннюю идею "спалиться на движении при
  разморозке" из исходного ТЗ. Если понадобится вернуть — однострочная правка
  условия фазы в `FreezeService`.

**Документация:** обновлены `ARCHITECTURE.md` (новый RemoteEvent, новая
структура `CatchService`/`FreezeService`, зависимость `FreezeService` →
`RoundManager`), `DECISIONS.md` (новые пункты 12 и 13), `TASKS.md` (два
дизайн-пункта из Раздела 0 перенесены в выполненные, добавлены сценарии
ручного тестирования для line-of-sight, видимости подсказки и гейтинга позы).
