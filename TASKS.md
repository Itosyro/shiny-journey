## РАЗДЕЛ 0. Найденные при ревью проблемы

Список составлен в ходе аудита Opus (2026-07-05). Отсортирован по приоритету.
Помечены галочкой те, что **уже исправлены** в этом же ревью.

### Критичные (безопасность/краш)

- [x] **[КРИТ] Эксплойт `fireproximityprompt` в поимке.**
  `CatchService.lua` — серверный `Triggered` не проверял дистанцию, читер мог
  ловить всех Hiders с любой точки карты. → Добавлена серверная проверка
  расстояния (`seekerIsCloseEnough`) + настройки в `GameConfig`. Исправлено
  описание в `DECISIONS.md` п.4.
  ✔ Критерий: попытка "поймать" издалека серверно отклоняется.

- [x] **[ВЫС] Игровой цикл мог умереть навсегда от одной ошибки.**
  `RoundManager.gameLoop` — тело раунда не было изолировано. → Обёрнуто в
  `pcall` с аварийной уборкой и возвратом в лобби.
  ✔ Критерий: искусственная ошибка внутри фазы не вешает сервер, следующий
  раунд стартует.

- [x] **[ВЫС] Выход Hider посреди раунда ломал досрочное завершение.**
  `CatchService` не убирал вышедшего из `foundState`, поэтому `CountRemaining()`
  никогда не доходил до 0. → Добавлен `PlayerRemoving`-обработчик.
  ✔ Критерий: если один из трёх Hiders вышел, поимка двух оставшихся завершает
  раунд досрочно.

- [x] **[СРЕД] `JumpHeight` обнулялся при позе, но не восстанавливался.**
  `FreezeService` — на ригах `UseJumpPower=false` игрок навсегда терял прыжок
  после первой позы. → Кешируем исходные `walkSpeed/jumpPower/jumpHeight` и
  восстанавливаем.
  ✔ Критерий: после разморозки игрок прыгает как до неё.

### Дизайн-решения — приняты автором и внедрены (2026-07-05)

- [x] **[СРЕД, дизайн] Промпт поимки раскрывал позицию Hider.**
  Решение автора: подсказка видна **только Seekers** (Hiders её вообще не
  видят — скрывается персонально на клиенте через новый RemoteEvent
  `HideCatchPromptsFromHiders` + `CatchClient.lua`), имя убрано из текста
  (остался нейтральный `ActionText = "Поймать"`), включена
  `RequiresLineOfSight = true` **плюс** её же дублирующая серверная
  raycast-проверка в `CatchService.hasLineOfSight` (встроенное свойство —
  только клиентская проверка, обходится тем же эксплойтом, что и дистанция).
  См. `DECISIONS.md`, п.12.
  ✔ Критерий выполнен: Hider не видит подсказки над другими Hiders; Seeker не
  видит имени цели; поимка через стену/без прямого взгляда отклоняется
  сервером.

- [x] **[НИЗ, дизайн] Заморозка не была ограничена ролью/фазой.**
  Решение автора: вставать/выходить из позы может только Hider, и только во
  время фазы `Hiding` (не `Seeking`). Проверка добавлена в
  `FreezeService.onRequestFreeze` (роль + `RoundManager.State`), клиентская
  кнопка в `FreezeClient.lua` скрыта для Seekers и неактивна вне `Hiding`.
  См. `DECISIONS.md`, п.13 — там же зафиксирован сознательный компромисс:
  теперь Hider не может выйти из позы и во время `Seeking`, что убирает
  задуманную в исходном ТЗ механику "спалиться на движении при разморозке".
  Если захотите её вернуть — это одна строка условия в `FreezeService`.
  ✔ Критерий выполнен: Seeker не может встать в позу (сервер отклоняет,
  кнопка скрыта); Hider не может переключить позу в фазе `Seeking`.

### Не исправлено (более мелкое, не блокирует живой тест)

- [ ] **[НИЗ] Магические числа скорости (16/50) в двух местах.**
  `RoundManager.setWalkable` и дефолты в `FreezeService` хардкодят WalkSpeed/
  JumpPower. Вынести в `GameConfig`, а лучше — кешировать исходные значения
  Humanoid (как уже сделано для позы).
  ✔ Критерий: изменение скорости — в одном месте конфига.

## РАЗДЕЛ 1. Живой тест через Roblox Studio (MCP) — следующий крупный шаг

- [ ] Установить Rojo: плагин в Studio (Toolbox → "Rojo") + CLI по инструкции
  с rojo.space.
- [ ] Запустить `rojo serve` в папке проекта, в Studio нажать Rojo → Connect.
  ✔ Критерий: дерево `src/` разложилось по сервисам согласно
  `default.project.json` без ошибок.
- [ ] Первый прогон в Play: проверить, что проект **компилируется без ошибок**
  (проверить Output на красные ошибки), сервер стартует
  (`[MecchaChameleon] Сервер инициализирован`), клиент стартует.
  ✔ Критерий: два игрока (Play → 2 players) видят HUD и палитру.
- [ ] Создать в Workspace `Part` с именем `SeekerWaitingRoom`.
  ✔ Критерий: в фазе Hiding искатель телепортируется в эту комнату.
- [ ] Проверить покраску: выбрать часть тела, тапнуть цвет — тело красится,
  заряды убывают; пипетка берёт цвет поверхности.
  ✔ Критерий: цвет виден и второму игроку (репликация).
- [ ] Проверить полный цикл раунда вживую (Lobby → Hiding → Seeking → RoundEnd).
  ✔ Критерий: экран итогов показывает очки, игра возвращается в лобби.

## РАЗДЕЛ 2. Полировка MVP-механик

- [ ] **Анимация позы.** Загрузить реальную анимацию в Studio, подставить ID в
  `GameConfig.POSE_ANIMATION_ID` вместо заглушки `rbxassetid://0`.
  ✔ Критерий: при заморозке персонаж принимает статичную позу, ходьба не
  проигрывается.
- [ ] **Несколько поз.** Сейчас поза одна. Сделать список Animation ID и выбор
  позы игроком (или случайную).
  ✔ Критерий: игрок может выбрать хотя бы из 2–3 поз.
- [ ] **UI-полировка палитры под touch.** Проверить размеры кнопок на реальном
  телефоне (свотчи 44px, кнопки частей тела), читаемость, не перекрывает ли
  палитра джойстик/прыжок на мобиле.
  ✔ Критерий: на телефоне всё нажимается пальцем, ничего не налезает.
- [ ] **Балансировка.** Проверить тайминги (Hiding 30с / Seeking 120с) и формулу

  ✔ Критерий: раунд не ощущается слишком коротким/длинным на плейтесте.

## РАЗДЕЛ 4. Ручное тестирование (сценарии для Studio)

Прогнать каждый сценарий вручную и отметить результат:

- [ ] **2 игрока (минимум).** 1 Seeker, 1 Hider — раунд идёт, поимка работает.
- [ ] **10 игроков (максимум).** Роли раздаются (2–3 Seekers), не лагает.
- [ ] **Выход Seeker посреди раунда.** Игра не падает, раунд доигрывается.
- [ ] **Выход Hider посреди раунда.** Досрочное завершение считается корректно
  (см. фикс в Разделе 0).
- [ ] **Попытка красить во время позы.** Сервер отклоняет покраску.
- [ ] **Попытка красить в фазе Seeking.** Сервер отклоняет (маскировка "заморожена").
- [ ] **Поимка издалека (эксплойт).** По возможности проверить, что серверная
  проверка дистанции отклоняет поимку не вплотную.
- [ ] **Поимка через стену.** Искатель рядом с Hider, но между ними стена —
  сервер отклоняет (проверка line-of-sight, см. `DECISIONS.md` п.12).
- [ ] **Видимость подсказки "Поймать".** Два Hiders подходят друг к другу —
  подсказка над соседом НЕ появляется. Seeker подходит к Hider — подсказка
  появляется, без имени игрока.
- [ ] **Seeker пытается встать в позу.** Кнопка не видна / сервер отклоняет
  `RequestFreeze` (см. `DECISIONS.md` п.13).
- [ ] **Hider пытается сменить позу во время Seeking.** Кнопка неактивна,
  сервер отклоняет — поза остаётся такой, какой была на конец Hiding.
- [ ] **Пустой сервер / 1 игрок.** Висит в Lobby, не стартует, не падает.
