## РАЗДЕЛ 0.8. Система очков: Missed Point Ranking (2026-07-06)

По прямому указанию автора: в оригинале есть механика "Missed Point
Ranking" - Hider получает очки не просто за побег в дальний угол, а за то,
что остаётся в зоне видимости Seeker'а и всё равно не замечен. Поощряет
маскировку "у всех на виду", а не только уклонение. Обоснование - см.
`DECISIONS.md`, п.22.

  дистанции/прямого взгляда (raycast), которая раньше была продублирована
  только внутри `CatchService`. `CatchService.lua` переведён на этот модуль
  (убрано дублирование, поведение поимки не изменилось).
- [x] `GameConfig.lua`: `MISSED_POINT_CHECK_INTERVAL_SECONDS` (1.5с),
  `MISSED_POINT_MAX_DISTANCE` (50 - заметно больше дистанции поимки),
  `MISSED_POINT_PER_TICK` (3), `SURVIVAL_BONUS_POINTS` (50, флат-бонус за
  то, что дожил до конца раунда - отдельно от очков за каждую секунду).
- [x] `ScoreService.lua`: фоновый цикл `missedPointWatchLoop` (раз в
  `MISSED_POINT_CHECK_INTERVAL_SECONDS`, паттерн "токена раунда" как у
  `WhistleService.watchLoop`) - проверяет каждого живого Hider против всех

  счётчик сам останавливается, когда Hider становится Seeker в Infection -
  без необходимости знать о мутациях `RoundManager.currentHiders/Seekers`.
- [x] Новый RemoteEvent `MissedPointRankingUpdate` (сервер → **только сам
  Hider**) - личный, действующий в реальном времени фидбек. **Явное

- [x] `HUDBuilder.lua`/`RoundUIClient.lua`: новый лейбл "Замечен, но не

- [x] `ResultsUIBuilder.lua`: экран итогов теперь показывает "🏆 Топ раунда"
  (топ-3 по `roundScore`) и, если кто-то заработал очки маскировки, "🎭
  Лучшая маскировка раунда" (максимум `missedPoints`) - перед полным
  списком участников.
- [x] Подтверждено (без изменений кода): очки Infection-игрока (был Hider,
  стал Seeker) уже складываются корректно - `roundScores` это плоская

### Live Test Findings

**Среда:** Claude Code on the web (облачный контейнер), сессия без
установленного MCP-коннектора Roblox Studio.

**Что произошло при попытке:** вызов `ListConnectors` с ключевыми словами
`["roblox", "studio", "mcp"]` вернул пустой список - ни один MCP-сервер с
таким названием не подключён к этому аккаунту/сессии. Поиск инструментов
по ключевым словам "roblox studio"/"playtest" также не нашёл ни одного
инструмента. Никакой ошибки подключения не было - подключаться было
физически не к чему, MCP-плагин Roblox Studio в принципе не значится
доступным в этой среде.

**Почему это ожидаемо:** Roblox Studio - десктопное GUI-приложение
(Windows/Mac), а не веб-сервис. MCP-плагин для него (Rojo/сторонний
Roblox Studio MCP) должен быть запущен на машине, где физически открыта
Studio, и слушать локальное подключение оттуда. Облачная сессия Claude
Code на web не имеет доступа к чьему-либо рабочему столу - только к
изолированному Linux-контейнеру с файлами проекта.

**Что нужно сделать автору (простыми словами), чтобы живой тест всё-таки
состоялся:**
1. Открыть Roblox Studio на своём компьютере (Windows/Mac).
2. Установить плагин Rojo в Studio (через Toolbox, поиск "Rojo") - это для
   синхронизации файлов, отдельно от вопроса живого автотестирования.
3. Если нужен именно автоматический playtest с чтением логов через
   Claude - использовать **Claude Code, запущенный локально на своём
   компьютере** (не в этой веб-сессии), с настроенным MCP-сервером Roblox
   Studio (если такой плагин у автора есть/будет установлен) - тогда
   сессия сможет напрямую общаться с открытой на этом же компьютере Studio.
4. Альтернатива без автоматизации: подключиться через обычный Rojo
   (`rojo serve` + Rojo-плагин в Studio → Connect), нажать Play вручную
   вдвоём (или Play → Start Server + несколько клиентов), и вручную
   прогнать сценарии из Раздела 4 этого файла, читая Output-панель Studio
   на предмет красных ошибок.

**Обновление (2026-07-08):** автор прислал команду для локальной установки
MCP-плагина Roblox Studio (`claude mcp add ... %LOCALAPPDATA%\Roblox\

## РАЗДЕЛ 4. Ручное тестирование (сценарии для Studio)

Прогнать каждый сценарий вручную и отметить результат:

- [ ] **2 игрока (минимум).** 1 Seeker, 1 Hider — раунд идёт, поимка работает.
- [ ] **10 игроков (максимум).** Роли раздаются (2–3 Seekers), не лагает.
- [ ] **Выход Seeker посреди раунда.** Игра не падает, раунд доигрывается.
- [ ] **Выход Hider посреди раунда.** Досрочное завершение считается корректно
  (см. фикс в Разделе 0).
- [ ] **Попытка рисовать во время позы.** Сервер отклоняет пакет мазков
  (`PaintService.onPaintStroke`, проверка `paintingBlocked`).
- [ ] **Попытка рисовать в фазе Seeking.** Сервер отклоняет (маскировка
  "заморожена" - `RoundManager.State ~= "Hiding"`).
- [ ] **Seeker пытается рисовать/красить.** Сервер отклоняет (роль не Hider).
- [ ] **Чернила заканчиваются.** При долгом непрерывном рисовании чернила
  доходят до 0, новые мазки перестают наноситься, но уже нанесённые остаются;
  чернила восстанавливаются со временем.
- [ ] **Свисток: автоматический.** Hider ничего не делает 45 секунд в фазе
  Seeking - звук проигрывается сам, таймер сбрасывается.
- [ ] **Свисток: ручной.** Hider жмёт "Свистнуть" раньше автоматического -
  звук проигрывается сразу, таймер сбрасывается на полный интервал.
- [ ] **Свисток пойманного Hider.** После поимки автосвисток для этого игрока
  больше не срабатывает.
- [ ] **Дальность свистка.** Игрок далеко (за пределами `RollOffMaxDistance`)
  не слышит звук, игрок рядом - слышит.
- [ ] **Поимка издалека (эксплойт).** По возможности проверить, что серверная
  проверка дистанции отклоняет поимку не вплотную.
- [ ] **Поимка через стену.** Искатель рядом с Hider, но между ними стена —
  сервер отклоняет (проверка line-of-sight, см. `DECISIONS.md` п.12).
- [ ] **Видимость подсказки "Поймать".** Два Hiders подходят друг к другу —

  появляется, без имени игрока.

- [ ] **Hider пытается сменить позу во время Seeking.** Панель скрыта,

  позу (после загрузки финальных анимаций), `HipHeight` меняется по
