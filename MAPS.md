# MAPS

Обзор поиска готовых карт/мебели для режима "прятки в помещении" и итоговое
решение по первой играбельной карте проекта. Обновляется при добавлении
новых карт.

## Итог (TL;DR)

Готовой карты/набора мебели, которую можно **легально встроить как файл в
этот репозиторий**, найти не удалось — см. "Почему ни один вариант не
подошёл" ниже. Вместо этого написан собственный процедурный генератор
карты — `src/ServerScriptService/MapBuilder.lua`. Он не требует внешних
ассетов, не имеет вопросов по лицензии (весь код написан с нуля для этого
проекта) и полностью проходит через Rojo как обычный Luau-скрипт.

## Почему ни один вариант не подошёл

**Варианты 1-3 (Roblox Marketplace / Creator Store / Library-ассеты).**
Технически это не скачиваемые файлы, а ID ассетов, вставляемых в проект
только через кнопку "Insert" в открытой Roblox Studio — у этой сессии нет
доступа к Studio (см. `TASKS.md`, Раздел 1, "Live Test Findings"), поэтому
физически нечего было бы положить в `src/`. Но даже если бы доступ был:
согласно [Roblox Terms of Use](https://en.help.roblox.com/hc/en-us/articles/115004647846-Roblox-Terms-of-Use)
и [Creator Store Terms](https://en.help.roblox.com/hc/en-us/articles/21308223046932-Creator-Store-Terms),
ассеты Marketplace/Creator Store **нельзя использовать вне Roblox Studio и
запрещено сдавать в аренду, продавать, распространять или сублицензировать**
— выгрузка ассета в виде `.rbxm`-файла и коммит этого файла в открытый
GitHub-репозиторий прямо нарушает эти условия, даже если сам ассет
помечен автором как "бесплатный".

**Вариант 4 (Blender-файл).** Не формат Roblox вообще — потребовал бы
отдельного пайплайна конвертации через Blender и повторной загрузки через
Studio (тот же недостающий доступ), плюс лицензия не расписана детально.

**Вариант 5 (`.rbxl`-шаблон целой игры).** Ближе всего к нужному жанру, но
автор **не указал явную лицензию** — по умолчанию это означает "все права
защищены" (стандартное авторское право), значит нельзя ни встраивать в
свой репозиторий, ни публиковать производную работу без явного разрешения
автора. К тому же это цельный `.rbxl` (весь Place целиком, со своими
скриптами и системами), а не отдельная карта — конфликтовал бы с уже
написанной архитектурой проекта (`RoundManager`, `PaintService` и т.д.).

**Общий вывод:** ни для одного из вариантов 1-5 нет пути "скачал файл →
положил в `src/Maps/` → Rojo синхронизировал", который был бы одновременно
технически возможным в этой облачной сессии (без Studio) и юридически
чистым для публичного репозитория. Поэтому выбран путь, прямо
предусмотренный ТЗ как запасной: собственный процедурный генератор.

## Выбранное решение: `MapBuilder.lua` (процедурная карта)

`src/ServerScriptService/MapBuilder.lua` — `ModuleScript`, который при
старте сервера (`Main.server.lua`, до `RoundManager.Start()`) кодом
строит карту из примитивов `Part` прямо в `Workspace`. Подробности
конструкции — в `ARCHITECTURE.md`, раздел "Карта".

Почему это лучше, а не просто "пришлось":
- **Ноль вопросов по лицензии** — весь код написан с нуля для этого проекта.
- **Полностью версionируется в Git и синхронизируется Rojo** как обычный
  Luau-файл (в отличие от `.rbxm`, для которого потребовался бы либо Studio,
  либо бинарный файл в репозитории, что плохо сочетается с текстовым diff).
- **Мгновенно правится без Studio** — поменять размер комнаты, число
  предметов или зоны — это правка чисел в Lua-таблице, а не пересборка
  ассета в другой программе.
- Даёт **разнообразие цветов/размеров мебели "из коробки"** (важно для
  механики маскировки кистью) — см. `ARCHITECTURE.md`.

Если в будущем у автора будет открыта Roblox Studio и он самостоятельно (или
через локальную сессию Claude Code с MCP-плагином Studio — см. `TASKS.md`)
вставит купленную/бесплатную карту из Marketplace через Toolbox — это не
конфликтует с `MapBuilder.lua`: генератор достаточно не запускать (одна
строка в `Main.server.lua`) или явно отключить константой в `GameConfig.lua`.
