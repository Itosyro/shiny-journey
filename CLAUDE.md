# CLAUDE.md — правила работы над проектом MECCHA CHAMELEON Clone

Я (Claude) — единственный разработчик и геймдизайнер этого проекта. Автор и его
друг НЕ программисты и не пишут код. Они описывают простыми словами, что хотят

- пишу весь Luau-код;
- поддерживаю структуру проекта, готовую к синхронизации с Roblox Studio (вручную
  или через Rojo);
- веду документацию проекта, чтобы работу можно было продолжить в любой новой
  сессии или даже с другой нейросетью без потери контекста.

## Референс

Клонируем механики игры **MECCHA CHAMELEON** (Steam):
https://store.steampowered.com/app/4704690/MECCHA_CHAMELEON

Суть оригинала: Seekers (искатели) vs Hiders (прячущиеся). У Hiders изначально
белое тело. Они красят себя под фон локации и замирают в позе, имитируя предмет
интерьера. Seekers должны найти всех до конца таймера. Публичные лобби на
2–24 игрока в зависимости от режима/карты (см. `DECISIONS.md`, п.19), игра
дружелюбна к стримингу.

## Целевая платформа

Финальная игра должна быть полностью оптимизирована под **мобильный Roblox**:
- touch-управление, крупные кнопки, адаптивный UI под разные размеры экрана;
- лёгкая производительность для слабых телефонов (минимум тяжёлых эффектов,
  никаких дорогих Raycast-циклов на каждый кадр без надобности).

## Обязательные правила работы (соблюдаются на всём протяжении разработки)

1. После каждого значимого изменения — обновлять все файлы документации
   (README.md, ROADMAP.md, TASKS.md, CHANGELOG.md, DECISIONS.md).
2. После каждого завершённого блока работы делать `git commit` с понятным
   сообщением на русском, кратко описывающим суть изменения, и сразу `git push`.
3. Если нет уверенности в актуальном API Roblox, синтаксисе Luau, лимитах
   сервисов или лучших практиках — ОБЯЗАТЕЛЬНО искать в интернете перед
   написанием кода. Никогда не выдумывать несуществующие функции или
   устаревшие API.
4. Писать код с расчётом на подключение через Roblox Studio MCP в будущем —
   соблюдать стандартную структуру сервисов (ServerScriptService,
   ReplicatedStorage, StarterPlayer, StarterGui и т.д.) и стандартные
   соглашения именования файлов Rojo (`*.server.lua` = Script, `*.client.lua`
   = LocalScript, `*.lua` = ModuleScript).
5. Каждый скрипт снабжать короткими комментариями на русском простыми
   словами — авторы проекта не программисты, они должны понимать логику.
6. Всегда оптимизировать под мобильные устройства: touch-friendly UI, минимум
   тяжёлых визуальных эффектов, крупные элементы интерфейса.
7. Перед каждым новым крупным этапом кратко сверяться с TASKS.md, чтобы не
   терять последовательность и не дублировать работу.

## Стиль кода

- Luau, без внешних зависимостей.
- Сервер — источник истины (server-authoritative): клиент только предлагает
  действие (цвет, позу, поимку), сервер проверяет и применяет.
- UI строится кодом (`Instance.new`) в LocalScript, а не собирается вручную в
  Studio — так весь интерфейс версионируется вместе с остальным кодом и
  синхронизируется через Rojo без ручной пересборки.
- Общие константы и баланс выносятся в `ReplicatedStorage/Modules/GameConfig.lua`,
  чтобы менять баланс без правки логики.
- Минимум комментариев, но обязательно объяснять неочевидные решения (почему
  сделано именно так), а не то, что и так понятно из кода.

## Текущий статус

Смотри `TASKS.md` (список задач), `ROADMAP.md` (этапы) и `ARCHITECTURE.md`
(реальная архитектура кода). Коротко: MVP написан в коде (лобби → прятки →
поиск → итоги), проведён аудит Opus — исправлены критичные баги (уязвимость
поимки через `fireproximityprompt`, защита игрового цикла от падения, выход
игрока посреди раунда, восстановление прыжка после позы). После аудита
механика покраски полностью пересмотрена: вместо кнопок "часть тела + цвет"
теперь свободное рисование кистью (мазки-`Texture` вместо `EditableImage` —
обоснование в `DECISIONS.md`, п.14), плюс добавлена новая механика свистка у
Hiders (`DECISIONS.md`, п.15). Затем поза тоже пересмотрена: вместо одной
произвольной заморозки — выбор из 4 конкретных пресетов (присесть/лечь/
прислониться/замереть стоя, `DECISIONS.md` п.17), и добавлен режим Infection
по умолчанию — пойманный Hider не выбывает, а сразу становится Seeker
(`DECISIONS.md` п.18); режим Classic заложен архитектурно, переключается
константой в `GameMode.lua`. Затем баланс ролей пересмотрен на диапазон
2–24 игрока (раньше ошибочно считали 6–8, `DECISIONS.md` п.19), добавлены
приватные комнаты с паролем через TeleportService + MemoryStoreService
(`DECISIONS.md` п.20), полноценный режим зрителя для зашедших посреди
раунда (`DECISIONS.md` п.21) и экран лобби. Перед коммитом этого блока
работы код прогнан через code-review skill — найдены и исправлены 2
реальных бага (см. `DECISIONS.md`, п.20–21 и `TASKS.md`, Раздел 0.7). Код
**ещё не тестирован вживую** в Roblox Studio — это следующий этап
(«Live-тестирование и полировка», см. ROADMAP). Приватные комнаты
дополнительно нельзя проверить даже в Studio Play-режиме — только после
публикации игры (TeleportService не работает при тестировании). Открытых
дизайн-вопросов на данный момент нет. Осталось несколько чисто технических
задач (реальные ассеты вместо заглушек `rbxassetid://0` для мазка/свистка/4
анимаций поз, визуальная калибровка, выставить `MaxPlayers` в Creator
Dashboard) — см. `TASKS.md`, Разделы 0.5, 0.6 и 0.7.
